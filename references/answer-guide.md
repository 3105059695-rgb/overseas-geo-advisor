# 内置答题与时效规则

安装者只需提供仓库地址，使用者只需提问。本文件是 AI 的执行规则，不要求用户每次复制或重述。与 SKILL.md、evidence-policy.md 和 workflow-v0.5.md 一起使用；本文件管问题理解、时效与表达，字段合同和证据资格分别以另外两份文件为准。

## 先确定要回答什么

默默确认四件事：用户问谁、想知道什么关系、哪个时间范围、希望拿到清单还是解释或操作方法。结合必要前文理解“那 Grok 呢”，更新对象但保留原来的问题。只有歧义会实质改变答案时才问一个短问题；能合理推断时说明关键假设并继续。

| 用户问题 | 答案必须给出的内容 | 不能拿来代答的旁支 |
|---|---|---|
| 海外 AI 搜索平台有哪些 | 具体产品、用途与差异；能力按当次官方资料核查 | 只有术语定义，没有产品 |
| Claude 和 Grok 更常引用哪些信源 | 分平台的来源类型、具体网站与观察范围；若某项未披露就说清 | 爬虫名单、能访问哪些网站、用它写 SEO 的方法 |
| 海外信源怎么分 | 分类依据、每类作用与例子；品牌关系与内容形式分开 | 把“官网、视频、权威、高优先级”混成同一层分类 |
| 我的英文网站怎么做 GEO | 结合已知业务给步骤、示例、产出和检查方法 | 没有依据的固定投入顺序或效果保证 |
| 这篇论文/帖子讲什么，能否照做 | 方法、观察结果、适用条件与限制；作者建议单独归因 | 将个案经验升级为普遍有效的方法 |

先分平台、行业或子问题检索。可用中英文术语改写并回读方法、结果和局限。若只有无关候选，有限次改写后联网补查；不要用不相干的库内材料填满答案，也不要从有限结果声称全库没有。

## “最新”是当次核查，不是改一下日期

默认以实际提问当天为核查日；用户指定历史时间时按那个时期回答。

| 情况 | 做法 |
|---|---|
| 稳定概念、计算方法或指定历史论文 | 先按库内原文解释；不为显得新而寻找无关新文章 |
| 当前产品能力、模型、价格、政策 | 查库取得背景，再打开相关平台的当前官方资料核查 |
| 当前信源偏好、排名、引用占比、近期效果 | 查库后寻找原始研究或数据发布者，核对采样期、题域、地区、模型、模式、分母；不只看文章发布日期 |
| 只找到旧的相关研究 | 保留其实际观察日期，讲清可得结论；当前外推标为未确认 |
| 没有联网能力、打开失败或只拿到搜索摘要 | 如实记录不可用或失败；不能宣称最新事实已核实 |
| 用户要求仅用知识库或禁止联网 | 遵守；说明知识库证据日期与当前信息缺口 |

联网先找较新的、条件匹配的可靠原始来源；必要时扩大时间范围。不把“最近 30/90 天”设为机械门槛，更近的发布日期不能弥补方法缺失或对象不符。引用率等数字必须追到原始测量，营销转述只作线索。

保存四类时间：来源发布/更新日期、实际观测/生效时间、归档收录时间、当次核查时间。正文至少给来源日期、影响结论的观测时间和核查日；未知就写未披露。今天核查的 6 月研究仍是 6 月数据。禁止因转载、收录或重新打开而刷新事实年龄。

有冲突时先比较题域、地区、产品模式、版本、采样与分母。条件不同则并列说明；条件相似但结论冲突则保留争议，不能仅按“新文章胜过旧文章”裁定。

知识库固定于随 Skill 发布的数据版本。用户新增的 Obsidian/飞书内容不会自动进入这个快照；联网补充也不自动写回库内。更新 Skill、发布新快照与当次查最新网页是三件事。不要通过跳过完整性校验或猜测分支来伪装数据更新。

## 用小白能理解的方式组织答案

先用一两句话回答，再展开真正需要的解释。长度随问题复杂度，不强制把每个问题写成报告。

1. **回答本题。**比较题逐一覆盖对象；名单题给名字；方法题给行动。不要先输出检索日志或一整段免责声明。
2. **讲清含义。**第一次用术语时配普通中文解释，例如“信源，就是回答引用的网页或帖子”；百分比写清分母。解释目的和因果链，不能只堆术语。
3. **就近放依据。**每项关键结论旁给可打开的原始链接、来源日期和必要条件。必要时用一小段原文或标为译文的短摘录说明依据，遵守引用长度限制。
4. **例子帮助理解。**标明教学例子、作者案例或本次实测，三者不可互换；概念题不强塞整套执行方案。
5. **说清实际用途。**若问题需要行动建议，写明哪些由来源直接支持，哪些是基于用户条件的推导；不给没有证据的保证。
6. **收尾只留影响判断的缺口。**资料不全时仍先回答已知部分，不把“不确定”当作停止解释的理由。

对于“Claude 和 Grok 更喜欢引用哪些信源”，可采用以下骨架，但必须重新检索，不填预设网站名单或沿用旧比例：

- 开头：分别概括两平台在已核对题域中的观察。
- Claude：具体来源类型/网站 → 研究时间及样本 → 一句普通话解释。
- Grok：同样的结构；不同题域分开，不与 Claude 的另一类样本硬比高低。
- 需要时解释对用户业务意味着什么，标为建议或推断。
- 文末注明核查日、尚未覆盖的时间或范围、库内与联网补充的实际使用情况。

表格有助于对比时再用。不要把所有日期、型号、分母挤进开头，但也不能藏掉足以改变结论的条件。正文不放长哈希、JSON 或工具成功状态。

## 交付前必须完成的核对

按照 workflow-v0.5.md 执行 prepare、adjudicate、check。由 AI 自行写临时文件并作语义判断；只用允许采用的陈述生成事实，改写不能扩大范围。

- 对题：每个被问对象和关系都有回答或具体缺口。
- 对证据：来源原文确实支持该句，平台与表格行没有串用；搜索到不等于引用过，引用多不等于导致推荐。
- 对时间：当前结论已做当次核查，历史观察保留历史范围；数据日期未知不编造。
- 对数字：没有拼接不同比例、重复计算同源证据或更换分母。
- 对表达：术语有解释，例子有标识，小白能够理解这项信息对问题有什么用。

程序检查通过仍不是独立事实审核。只报告实际执行的查询、回读和核查；可用一句“本次查阅知识库相关原文，并联网补充……；数据截至……”让用户知道是否真的查过。查询失败就说失败；库内候选全不支持时，明确本题结论来自联网补充，而不伪称知识库已经包含。
