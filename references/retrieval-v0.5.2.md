# 文档、段落与附件的定位

保留 answer-guide.md 的解释方式；本文件处理“资料在库内，但没有拿到回答问题的段落”。

## 从文档定位到证据

- 用户给出完整标题、原始 URL 或文档 ID 时，优先按这些线索查找；识别出文档不等于已读完。
- 查看候选原文是否实际包含所问定义、步骤、实验结果或评论。如果只返回前言、目录、推广、其他术语，使用同一 document_id/source_version 做文章内搜索。
- 长论文按方法、结果、限制补读；词典使用术语及中英文别名；Reddit 评论保留楼主问题和父回复，不把单条反驳当成全帖结论。
- 文档范围内仍没有依据时，再进行有限次改写或其他来源检索。用户指定“这篇如何解释”时，其他资料只能作为明确标注的补充。

单独查找文章内段落：

```text
python -B -X utf8 scripts/geo.py search --question "grounding 依据锚定" --document-id <实际ID> --source-version <实际版本>
```

用于正式回答时，在分析 JSON 中增加范围，并重新生成完整证据包：

```json
{
  "resolved_question": "用户指定的词典如何解释 grounding？",
  "queries": ["grounding", "依据锚定"],
  "keywords": ["grounding", "依据锚定"],
  "source_scope": {
    "document_id": "由实际检索返回的ID",
    "source_version": "由实际检索返回的版本"
  }
}
```

然后照常执行 workflow prepare、adjudicate、check。source_scope 可附 start_line/end_line；文档和版本必须成对，不擅自改为最新版本。需要连续上下文时调用 read，按 next_start_line 补读；不能把片段上下文提示当成已经读取。

## 来源与时间

正文里的“原帖”“原文”“source”等主来源会与来源字段关联，发布日期、原文更新日期、观测期、归档日期分别保存。展示实际已知的日期；文件修改时间不作为发布日期。

同一论文的出处页、译稿和学习笔记可以互相导航，不能重复算成多份独立证据。导航记录不是事实来源；本轮来源只有库外网页时明确说明。

## 图片与 PDF

read 返回的 attachments 提供状态、原引用、公开 URL、文件大小和 SHA256；它们是正文之外的附件映射，正文版本和行号不变。

仅在回答确实需要图表或原始页面时，用客户端支持的图片/PDF能力打开标为 available 的公开链接。服务不会在安装时下载整套附件。原始引用为外站、缺失或有歧义时保留状态；不能猜地址、使用维护者电脑路径或把未打开的附件当作已读证据。

附件链接可访问与图中文字已被理解是两件事。需要说明图表内容时必须实际打开；已有文字图注可作为文字材料，但不等于看过整张图。
