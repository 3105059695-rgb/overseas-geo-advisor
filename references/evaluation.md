# 开发检查与内容验收

`tests/development_questions.json` 提供40个开发问题和必须/禁止事项。它是问题覆盖资产，运行工具没有异常不代表40题回答已经合格。

对每题分别记录候选检索、最终证据包、AI最终回答：

1. **候选证据召回：** 必需证据是否进入候选，不因同源多个文件重复计分。
2. **最终证据包覆盖：** 真正用于回答的片段是否保留方法、结果、条件与限制。
3. **事实支持：** 每项事实是否由原文支持，数字是否保留分母和时间。
4. **推导合理性：** 建议是否具有足够前提，业务条件是否成立，不确定性是否明确。
5. **主结论门槛：** 任何核心建议或优先级无依据，或遗漏足以改变建议的条件，都不能用整体95%支持率掩盖。
6. **用户结果：** 概念解释是否让用户理解；操作解释是否让用户明确下一步及所需材料。

程序验证只记录结构与资格，语义评分由对照原文的内容核验完成。当前源样稿由AI读取资料整理，尚未经独立领域专家验收。不要在报告中写成人工专家已审核。

独立40题应由未使用其答案调试的内容负责人准备，按问题意图、证据组合和业务条件与开发题区分，不能只换措辞。记录知识版本、模型、客户端和提示词版本。单独报告各题型分子/分母，以及真正经过GUI客户端展示验证的范围。

首版拟议指标沿用评审计划：候选Recall@20和最终关键证据覆盖≥90%、事实支持≥95%、必要要点完整性≥90%、引用可定位100%；主结论和重要优先级证据缺失为阻断项。这些是未来验收目标，不是当前自动脚本已测得的结果。

内容投入应按文章、论文、评论、表格/OCR分别记录实际核对时间后估算。先测少量样本，再承诺全库审核排期；30天动态资料核查、90天方法复查可作为待评审安排，由明确负责人维护。逾期动态信息只能作带日期的历史说明。
